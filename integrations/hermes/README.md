# Hermes → AIREP v0.2 integration evidence

**Hermes decides and enforces. AIREP preserves evidence of what Hermes reports it decided,
delivered, executed, and observed.**

This directory is a non-normative, first-party AIREP integration study against the public Hermes
source model. AIREP v0.2 is an experimental beta. There is no Hermes dependency on AIREP, no AIREP
dependency on Hermes, no Nous Research endorsement, and no independent interoperability or Hermes
adoption claim.

The deterministic scenarios are synthetic. Their canonical intent/action/instruction projections
are fixture-local and are not a production Hermes authorization contract. The integration does not
modify Hermes and does not rely on private Hermes queue fields as stable APIs.

## Contents

- [`MAPPING.md`](./MAPPING.md) defines the evidence-plane boundary, non-equivalences, digest rules,
  and scenario mapping.
- [`SOURCE_BASIS.json`](./SOURCE_BASIS.json) pins the AIREP and Hermes commits, issue/PR status, and
  reviewed Hermes blobs.
- [`UPSTREAM_GAPS.md`](./UPSTREAM_GAPS.md) lists only gaps confirmed against the pinned Hermes source.
- `fixtures/` contains eleven independently inspectable scenarios with native facts, signed
  artifacts, actual verifier results, actual reconciliation output, expectations, and a short README.
- `fixture_operator_inputs/` contains pinned **test-only public** bindings/revocation inputs used to
  exercise `AIREP-Authenticated` honestly.
- [`summary.json`](./summary.json) records every fixture result and a SHA-256 manifest digest for the
  complete fixture corpus.

The fixed Ed25519 seeds in the generator are labeled **TEST FIXTURE KEY — NEVER USE IN
PRODUCTION**. They are intentionally public and have no production authority. No private key file is
generated or committed.

## Regenerate and verify

From the repository root:

```bash
python3 integrations/hermes/generate_fixtures.py --regenerate
python3 integrations/hermes/generate_fixtures.py --check
python3 integrations/hermes/verify_fixtures.py
python3 -m unittest discover -s integrations/hermes/tests -v
```

`--regenerate` is required before generated files can be replaced. Generation happens in a temporary
directory first. `--check` performs a fresh generation and compares every generated byte with the
committed corpus.

The verification entry point uses the repository's actual AIREP v0.2 family schemas, tagged-hash
logic, Ed25519 class verifier, and reconciler. Fixture records reach `AIREP-Authenticated` only under
the committed test-only bindings and active revocation snapshot. That classification authenticates
the fixture producer binding/signature under those operator inputs; it does not establish report
truth, Hermes enforcement correctness, independent observation, or complete history.

## Interpretation limits

A valid fixture record or green test does not prove exactly-once consumption, replay prevention,
approver authentication, policy correctness, instruction delivery, execution, effect, or total
event-history completeness. Those properties require native evidence. Scenario 10 in particular
assumes a Hermes-native single-consumer outcome and verifies only that the mapping does not duplicate
successful AIREP lifecycle evidence for the rejected replay.

This work is first-party AIREP integration evidence against Hermes. It is not independent Hermes
adoption or independent AIREP interoperability.
